# Skill index file

`vault-search` reads a flat text index of every skill carried by every dormant plugin in the vault. The index is regenerated by `update-vault`.

## Path

Same parent as `inventory.json`:

```
$VAULT_DIR/skill-index.txt
```

(`$VAULT_DIR` resolved per `inventory-path.md`.)

## Format

One skill per line, pipe-delimited, no header:

```
<skill-name> | <plugin-name> | <one-line description>
```

Description is plain text, no pipes, ideally <= 100 chars. Newlines are stripped during generation.

Example:

```
trim-silence | audio-production | Trim leading and trailing silence from an audio file
denoise | audio-production | Remove background noise from an audio recording
zmanim | jewish-utilities | Return halachic times (zmanim) for a given date and location
```

## Why a flat text file

`vault-search` calls `grep -i` against this. A flat file means the search itself is cheap and the file is human-inspectable. JSON would force a parse step and add no value at this size.

## Generation

`update-vault` walks each plugin entry in `inventory.json`. If the entry has a `skills: [{name, description}, ...]` array, those rows are emitted directly. Otherwise the generator can attempt to scan installed plugin directories under the marketplace cache (best-effort, plugin-format dependent) and falls back to emitting a single placeholder row pointing at the plugin name.

The inventory remains the source of truth — auto-discovery is opportunistic.
